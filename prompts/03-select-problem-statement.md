# 03 — Select the problem statement

**Facilitator:** the goal is one problem statement the whole team owns. Claude drafts candidates; the team
votes. Use dot-voting (three votes each) on the screen or a whiteboard.

## Prompt

```text
Using the brief and what we saw in the running system, draft 5 candidate problem statements for this
project. Use this format for each:

  "<who> cannot <do what> because <cause>, which leads to <business impact>."

Under each one add:
- Evidence: two concrete facts from the brief or the corpus (cite page or file path).
- Measurable? How we would measure progress, or "hard to measure" and why.
- Size: small / medium / large for a half-day effort.

Make them really different: at least one about trust in answers, one about change safety (prompts and
policies change), and one about cost or operations. Then stop and ask us to vote. Do not pick for us.
```

## Team discussion

- Which statement would the CTO sign? Which one would Support care about most?
- Is any statement actually a solution in disguise ("we need dashboards")? Rewrite it as a problem.

## Gate

The team voted and one statement is selected. Write it on the board exactly as worded.
