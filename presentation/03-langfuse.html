Observability first

Four questions on every answer.

What happened?Every model call, tool call and retrieved fact, in order.traces
Was it good?Correct against ground truth. Grounded in the facts.scores
What did it cost?Tokens, money and seconds per question.cost · latency
What changed?Which prompt, model or code version produced it.versions
A status code answers none of these. Observability for agents starts with the trace.

Before we build

Eight rules for traces you can use.

1Stable, verb-first names. search-context, not fn_2.evaluators
2The right type. agent · generation · tool · retriever.filters
3Context everywhere. user, session, tags, environment.v4
4Record versions. Prompt name + version on the trace.compare
5Mask in the SDK. Emails → <email> before they leave.privacy
6Fail open. No keys or no Langfuse → the agent still answers.rule
7Flush on shutdown. Short jobs lose spans otherwise.jobs
8Summaries, not documents. Counts and paths, not 40 pages.cost

masking in prompt 08
