What is an eval?
"Evals give you a repeatable check of your LLM application's behavior. You replace guesswork with data, and catch regressions before you ship a change." · Langfuse docs
One eval has four partsexample on Q01
1 · inputQ01: Orion's refund, as of 2026-09-29
2 · outputThe agent's answer: "uptime 99.57% … Tomás approves"
3 · checkDoes it use the uptime valid on that date, 99.33%?
4 · scoreA value on the trace, e.g. partially_correct
Unit testSame input, same output, every time. assert answer == expected passes or fails once, and stays that way.
EvalThe answer changes every run. Score many runs and read the rate, not one result.

Eight rules for traces you can use.
1evaluators

Stable, verb-first names

search-context, not fn_2. Rules and filters match on the name.

the live rule filters on name = ask-orbisa
2filters

The right type

agent · generation · tool · retriever. The UI filters and colors by type.

search-context retriever, read-source tool
3v4

Context everywhere

user, session, tags, environment on every span, set early in the trace.

the CLI needed langfuse.* resource attributes
4compare

Record versions

Prompt name and version on the trace, so each version has its own numbers.

v1 vs v2: recall 0.889 → 0.873, rejected
5privacy

Mask in the SDK

Emails become <email> before they leave the process.

12 emails reached the agent, 12 <email> stored
6rule

Fail open

No keys or no Langfuse: the agent still answers. Tracing is never on the critical path.

Langfuse down → local prompt in under 10 s
7jobs

Flush on shutdown

Spans are sent in batches. A short job that exits first loses them.

run --rm agent exits right after the answer
8cost

Summaries, not documents

Counts and paths in metadata, not 40 pages of text.

facts_returned, hidden_as_future, source paths
