TO GET THIS RIGHT, AN AGENT MUST
  1. read a contract PDF, not only the policy
  2. ignore a page that is out of date
  3. add up two incidents from two postmortems
  4. know the approver changed in March
  5. cite where each fact came from
Tip

Design from the inside out. Take one problem at a time: read the contract, drop the stale page, add up the incidents, check who approves today, cite the source. Each step is something you can test and trace on its own.

Ground truth · why it matters

No ground truth, no proof.

An agent always answers, and it always sounds sure. Ground truth is the wall it cannot move: questions where people already know the right answer.

01 · humans Know the truth

Support, RevOps and Legal own the rules. Only they can say what "correct" means for Orion.

signs off every answer
02 · engineers Craft the file

Turn that knowledge into questions with an answer, facts, sources, a date and a trap.

reviewed like code, in git
03 · the system Gets measured

Every prompt and model version runs against the same 22 questions. Langfuse scores each one.

Tip

Write the trap first. If you cannot name the wrong answer a careless agent would give, the question does not test anything.

questionhuman

Taken from a real ticket or Slack thread, in the user's own words.

expected_answerhuman

Written and signed by the owner of the rule. Never by the model.

as_ofengineer

The date of the question. In 2025 the same question had another answer.

expected_factsengineer

1–5 small facts split from the answer. A judge checks each one.

expected_sourcesengineer

Exact file paths. Code checks the citations, no LLM needed.

traphumanengineer

The wrong answer a careless agent gives. It names what you test.

categoryengineer

Groups scores by failure type: temporal, conflict, false premise…

Agentic engineering today

Most of the work is in systems that already exist.

B2B platforms, large systems and acquired companies are not rebuilt. They are migrated, adjusted and extended, with an agent at your side.

Greenfieldthe exception
  • A blank repo. You pick the stack.
  • No users, no data, no history.
  • Mistakes are cheap.
Brownfieldthe normal job
  • Code, data and users already exist.
  • Old and new rules live side by side, like Brisklane and Orbisa.
  • Every change must keep what works working.
migrationsadjustmentsenhancementsintegrations after an acquisition
